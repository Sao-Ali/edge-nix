# Use edge-nix from another project

This directory is a separate flake with its own `model.onnx`, input fixture, and expected output. Its `flake.nix` adds `edge-nix` as a dependency and builds a portable archive.

From this directory, run:

```sh
nix build
tar -tzf result/edge-package.tar.gz
./result/bin/edge-validate @sample.json @expected.json
nix flake check
```

The archive contains only `manifest.json` and `model.onnx`. The `bin` commands in `result` run on the build host and are not part of the archive. Replace `model.onnx` with your own single-file ONNX model. Change the `modelFile` path in `flake.nix` if you use another filename. Replace `sample.json` and `expected.json` with inputs keyed by your model's input names and checks keyed by its output names. Set `maxModelBytes` for your model, or remove that setting if you do not need a size limit. Run `nix flake check` before transferring `result/edge-package.tar.gz` to a machine with compatible runtime dependencies. Commit the `flake.lock` generated by Nix in your own project to keep its input revisions fixed.

To test local changes to `edge-nix` before they reach GitHub, add `--override-input edgeNix path:../.. --no-write-lock-file` to a `nix build` or `nix flake check` command.

## Self-contained Arduino UNO Q bundle

On a native `aarch64-linux` Nix builder, this same consumer flake also exposes a
bundle configured in [`edge.nix`](edge.nix):

```sh
nix build .#uno-q
tar -tzf result/edge-inference.tar.gz
```

When using this checkout, add `--override-input edgeNix path:../.. --no-write-lock-file`
to the build command. Replace the model and both JSON fixtures in `edge.nix` for
your own model. The fixtures are required because the bundle runs validation
during the build. The archive includes its native runner and runtime libraries;
transfer `result/edge-inference.tar.gz` to the UNO Q Linux MPU.
